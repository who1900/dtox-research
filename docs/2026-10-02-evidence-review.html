01 / CORRECTNESS / GUARD VERIFIED + PUBLIC LABEL SMOKE

Full text follows acquisition, not an ID prefix

An arXiv/OpenAlex prefix does not prove body availability; an IACR record can have recovered open-access text. The fix is completeness(fulltext_source) and provenance(...) derived from actual acquisition metadata.

Abstract-only acquisition yields fulltext=false; missing metadata yields fulltext=null. A fetched PDF does not prove complete parsing: parse_completeness="unknown". PDF/Markdown is not promised as exact LaTeX.

Public VDF smoke returned four hits: two IACR records were abstract-only / false; the other PDF-backed records were true. Fragment hashes distinguish indexed text from returned snippets, but do not establish the truth of a claim.

02 / CORRECTNESS / GUARD VERIFIED + PUBLIC SCHEMA CONFIRMED

Strict is explicit; ordinary search defaults are unchanged

The public schema advertises search strict=False and bundle strict=True. Strict search forwards auto_relax=False; the API disables soft-layer expansion, filter relaxation and diagnostic broadening. Unknown terms are rejected before retrieval.

Regression coverage includes exact-layer named lookup, no unscored lexical fallback, and separate strict/non-strict cache keys. Ordinary search may broaden a request: read relaxed and matches_filters instead of presenting neighbouring results as exact matches.

03 / SECURITY / CRITICAL FALSE-SETTLEMENT GUARD VERIFIED

Wallet/key identities are not independent models

The pure helper excludes key:, wallet: and unspecified from model diversity. Wallet-only agreement remains read_once (pending); opposing decisive verdicts are contested.

Legacy arbitrary judged_by_model strings previously caused false confirmation or exclusion. The read-path fix accepts only server-established trusted-model: attribution for decisive readings. New attribution comes from info.reader_model/info.model, never client claims or key names.

Without verified model metadata, trusted settlement is unavailable and models=[] keeps agreement pending. Partial judgments cannot add model diversity. The public tool inventory contains no unsigned registry-write tools; the existing signed-verdict path authenticates signers, not independent reasoning.

A lead-verified count-only SQL check found zero legacy trusted-model:-prefixed records, without reading or exposing names. This does not turn legacy attribution into trusted agreement.

04 / ERROR HANDLING / GUARD VERIFIED · LOAD DISTRIBUTION UNKNOWN

Partial retrieval is not evidence of absence

partial survives mix/RRF and coarse fallback. _scored_results_for_audit(...) refuses partial retrieval with HTTP 503, even when a returned relevance score is high. Incomplete search is not a negative verdict.

Timeout/fallback guards are regression-tested. This does not establish a production latency distribution: no soak/load test was run, and p95 is not established.

05 / READ SURFACE / DEPLOYED + PUBLIC SMOKE CONFIRMED

A bounded research bundle, without verdict writes

get_research_bundle(query, layer=None, limit=3, max_chars=12000, strict=True) makes one POST to /v1/research/bundle with a 30-second internal request timeout and the shared read-tool HTTP/network error format. It does not write verdicts, create registry links or submit chain transactions.

Public EIP-4337 smoke with limit=1 and max_chars=6000 returned 10 code fragments, 3866 characters, in 1.17 seconds, with partial=false. This is one observed response, not p95 or an SLA.

Additional public fast-validation smoke completed in 11.56 seconds with error=null, as a pure-read operation. It reported external ERC-4337 candidate context, two unread candidates and no automatic confirmation. This is distinct from the 1.17-second bundle observation.
