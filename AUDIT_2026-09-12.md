## Product assessment

### Strengths

- Web3-first corpus combined with LLM and agent research
- Full-text, structure-aware evidence rather than abstract-only retrieval
- Equations, algorithms, code, tables, methods, results, and limitations are first-class chunks
- Hybrid dense and lexical retrieval with citation-graph expansion
- Cross-encoder reranking on ambiguous results
- Explicit source, URL, licence context, corpus snapshot, and full-text availability
- Claim registry separates retrieved similarity from prior human or agent judgments
- Scope and coverage signals reduce false novelty conclusions
- MCP, REST, and x402 interfaces expose the same evidence layer to different clients

### Operational risks

1. **High:** the current live MCP deployment still carries a shared internal API credential in its deployed source and exposes registry write tools. The public repository is already corrected: credentials are environment-only and registry writes default to disabled. The live migration must be performed before unrestricted public traffic.
2. **Medium:** a cold Qdrant search can occasionally exceed the upstream timeout while the corpus is large and actively growing. The x402 gateway now retries one transient read failure; repeated warm calls are fast. Latency should remain monitored by percentile, not average.
3. **Medium:** `validate_project` can take tens of seconds because it intentionally performs multiple retrieval, graph, registry, and reranking operations. This is acceptable for a deep audit but should be represented as an asynchronous or progress-reporting operation in a polished product UI.
4. **Medium:** the server disk was 88% occupied with about 49 GB free at audit time. Retention and alerting need to keep enough headroom for Qdrant compaction and snapshots.
5. **Low:** GitHub currently reports a Node runtime deprecation warning for official actions pinned by commit SHA. CI remains green; update the pinned action versions when upstream publishes Node 24 releases.

## Required final gate

Before opening the service broadly:

1. Move the live MCP internal API key into a root-readable environment file.
2. Deploy the public repository's fail-closed registry write gate.
3. Rotate the old shared API key after all internal services use the environment value.
4. Repeat MCP read-tool smoke tests and verify mutation tools reject anonymous calls.
